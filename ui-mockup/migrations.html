How "applied" is known

Today the scripts run every file in order with no history table, so re-running fails on files without IF NOT EXISTS. devdeck keeps a record of what ran where (file, checksum, time, who): Store it in: (•) devdeck's own local store   ( ) a devdeck_schema_history table in each database (shared with teammates on dev/uat).
First use on an existing DB: [Baseline: mark files up to … as already applied]. If an applied file's content changes later, it's flagged.

Config for this (in workspace YAML)

repos:
  infrabot-catalog-service:
    migrations:
      folder: schema/postgres
      pattern: "V{version}__{name}.sql"
      database: infrabot_catalog_db
      copy_to: ../eks_deployment/infrabot-migration/catalog-service
      runner: builtin          # or: script: "scripts/schema/apply-postgres-schema.ps1 -DockerContainer {container}"
