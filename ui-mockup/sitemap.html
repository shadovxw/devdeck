Implementation plan: devdeck/dev-plans/00-implementation-plan.md

Every page in the mockup and what it is for. Pages marked (detail) open from a row on the list page above them.

Overview

  • Home: today's view of the current workspace: stack status, errors, running pipelines, open work items, git sync state.

Code

  • Workspaces: one per codebase (infrabot, aws-central-portal, …). Create one, or clone one onto a new PC.
    • Workspace detail (detail): repos, stacks, flows, account rules, VS Code workspace file.
  • Repositories: every repo with which GitHub account it belongs to, branch, ahead/behind, pull/push.
    • Repo detail (detail): branches, changes, commits, PRs, account binding, runs for this repo.
  • Work Items: one per feature or bug fix (= one dev-plans/ folder). Stage tracker: plan → code → checks → review → PR.
    • Work item detail (detail): plan, changes, scan report, review, PR summary tabs.

Run locally

  • Stacks: named stack files (full, backend-only, …), each with a Start/Stop button.
    • Stack live view (detail): per-service status, ports, restart, last error.
  • Logs: all service output; filter by service, level, regex or JSON field; error list; saved filters.
  • Resources: CPU history, RAM per service, disk used by Docker, caches and node_modules; stop idle services, clean up disk. Summary also on Home.

Data (Postgres first)

  • Databases: Postgres servers per environment, which service uses which DB, migration status, what Claude can see.
    • Database explorer (detail): tables, columns, data preview, DDL, where it's defined and used in code.
  • Migrations: points at each repo's SQL migration folder; pending vs applied, dry run, run (built-in or your existing .ps1/.sh scripts), sync to eks_deployment, new migration written by Claude.
  • SQL Console: editor or psql terminal, results, export, history, environment safety rules.
  • Saved Scripts: your recurring SQL as .sql files with parameters; run from UI or as a flow step.

Pipelines

  • Flows: pipelines built from plugin steps (like infrabot workflows).
    • Flow builder (detail): trigger → steps → gates; each step's settings come from its plugin.
  • Runs: every flow run, its status and duration.
    • Run detail (detail): step-by-step result, logs, outputs passed to the next step.
  • Findings: all scanner + SonarQube + review issues in one list, with open-in-VS-Code links.
  • Images & Tags: docker image per service, latest tag on Docker Hub, next tag, build/push.

Platform

  • Plugins: every tool devdeck can use (git, github, docker, tilt, sonarqube, gitleaks, trivy, claude, …), installed version and health.
    • Plugin detail (detail): manifest: actions it provides, inputs/outputs, required binary, connection type.
  • Connections & Accounts: GitHub work account, GitHub group account, Docker Hub, SonarQube… plus rules that map repos to accounts.
    • Add / edit connection (detail): form rendered from the plugin's connection schema.
  • Notifications: channels (Windows toast, phone push via ntfy/Telegram, email via HTTPS API, Teams/webhook) and rules: service down, build done/failed, flow failed, digest. Works without SMTP.
  • Doctor: machine checks (Docker, Go, Node, tools, ports, git identity) and "set up this PC" bootstrap.
  • Settings: VS Code integration, paths, defaults.
